# v1.2 P2-03: independent pinned libuv evidence comparison

P2-03 adds a repeatability comparator around the existing pinned libuv
v1.48.0 evaluation and exercises the resulting external artifact through MCP
stdio. Each evaluation uses independent, clean original/instrumented builds from
the same immutable FaultDebug source snapshot and pinned libuv commit.

## Changes

- The external evaluator now performs MCP `initialize`, `tools/list`, and real
  `tools/call` requests for `open_fault`, `get_thread_trace`,
  `resolve_addresses`, `get_function_source`, and `get_call_relations`.
- It also submits an allowlist path-escape request and requires the server to
  return the expected tool error. Successful source and call-relation queries
  must remain bundle-verified and classified as `static_index` evidence.
- The instrumented CMake build and driver use stable debug/file prefix maps.
  Without them, debug paths in the static archive and driver changed their
  Build-IDs across otherwise identical clean builds.
- `compare_libuv_runs.py` compares the exact source/runtime identity, static
  archive hashes, driver Build-IDs, SIGABRT behavior, resolved libuv symbol and
  source semantics, source bundle/index hashes, and MCP success/error contract.
  It creates separate evidence tar archives and reads each archive back to
  verify its complete member/hash manifest.
- PID, absolute evidence paths, report time, runtime artifact bytes affected by
  ASLR/timestamps, event counts, RSS, and timings are explicitly excluded from
  semantic equality. Absolute bundle binary-source paths are location metadata;
  the manifest still compares the binary's exact hash and Build-ID.

## Limits

This is a Linux x86_64/Clang 18 evaluation of the pinned workload and current
source snapshot. It does not establish cross-platform behavior, general
libuv-application coverage, performance acceptance, or v1.2 release readiness.
The CI/package gate and current-revision 1800-second soak remain open.
