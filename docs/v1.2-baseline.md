## 확인한 첫 결함: 논리 이벤트 용량과 물리 배치

실제 `build-v12-baseline/test/fd_threads 1`을 실행했다. main과 worker가 각기
ENTER/EXIT를 기록한다. 독립적으로 native 물리 링 위치에서 읽은 기록과
`collect_mapping()`의 반환 결과를 비교했다. TID/함수 주소/시각 같은 실행별 값은
합격 기준으로 고정하지 않았다.

| 설정 | native 물리 슬롯 1 | 디코더 반환 |
| --- | --- | --- |
| `FAULTDEBUG_CONFIG=events=4096,threads=2` | generation 1, committed ENTER/EXIT 2건 | 슬롯 0·1 |
| `FAULTDEBUG_CONFIG=events=8,threads=2` | generation 1, committed ENTER/EXIT 2건 | 슬롯 0만 |

실제 물리 간격은 **196,648 bytes**, 슬롯 1 위치는 **196,728**이다.
작은 용량에서 디코더가 계산한 간격은 **424 bytes**다.
`faultdebug/format.py:144-146`이 논리 용량을 물리 스레드 간격에 사용하지만
`include/faultdebug/format.h:95-97`은 링의 이벤트 배열을 고정 크기로 선언한다.
`docs/format.md:29-36`에도 고정 배치가 명시되어 있다.

공개 `run_target()`으로도 같은 작은 설정을 실행했다. target은 정상 종료했고
`collector.ok=true`, `partial=false`, `complete=true`였으나 결과는 슬롯 0만
포함했다. 따라서 이 결과는 실제 수집 증거의 조용한 누락이다. 수정은
[P1-01](next-version-v1.2.md#3-작업-목록과-소유권)에서 진행한다.

## doctor 테스트 실패의 해석

`test/doctor_benchmark.py:82-85`는 `shutil.which`를 숨기지만 설치 package,
실행 가능한 wrapper, 고정 경로의 runtime 파일은 남아 있다. compiler 등 미가용
항목은 `NOT RUN`이고 `faultdebug/doctor.py:75-83`의 overall 상태도 `NOT RUN`이다.
같은 테스트의 line 48-54도 이 상태를 기대한다. line 84의 전역 `FAIL` 기대값과
충돌하므로 테스트 fixture와 상태 계약을 함께 정리한다. 미가용 도구를 무조건
`FAIL`로 바꿔 테스트를 맞추지 않는다.

이 섹션은 P1-02 수정 전 기준선 관찰이다. 이어서 수정·검증한 결과는
[P1-02 구현 보고서](v1.2-p1-02.md)에 있다. 그 결과에서는 missing-tool 단독 상태가
`NOT RUN`/exit 2이고 package 누락이 `FAIL`/exit 1이며, 같은 CTest 전체가 local
socket 허용 실행에서 12/12 통과했다.

## 재실행 명령

아래는 이 체크아웃의 준비된 `.venv`·`.tools`를 사용하는 예시다.
다른 호스트에서는 CONTRIBUTING의 Python 3.12 환경과 Clang 18을 먼저 준비한다.
`PWD`는 프로젝트 루트이며, virtualenv Python 경로를 `realpath`로 해제하지 않는다.
실제 agent/gRPC 검증에는 **로컬 Unix 소켓 및 loopback 사용이 가능한 실행 환경**이 필요하다.

```bash
export PATH="$PWD/.tools/bin:$PWD/.venv/bin:$PATH"
export FAULTDEBUG_REAL_CC="$PWD/.tools/bin/clang"
export FAULTDEBUG_REAL_CXX="$PWD/.tools/bin/clang++"
export FAULTDEBUG_RUNTIME_DIR="$PWD/build-v12-baseline"

cmake -S . -B build-v12-baseline -G Ninja \
  -DCMAKE_C_COMPILER="$FAULTDEBUG_REAL_CC" \
  -DCMAKE_CXX_COMPILER="$FAULTDEBUG_REAL_CXX" \
  -DPython3_EXECUTABLE="$PWD/.venv/bin/python" \
  -DFAULTDEBUG_PYTHON_EXECUTABLE:FILEPATH="$PWD/.venv/bin/python" \
  -DFAULTDEBUG_BUILD_TESTS=ON -DFAULTDEBUG_ENABLE_PROVENANCE=ON
cmake --build build-v12-baseline --parallel 2

.venv/bin/python -m compileall -q faultdebug scripts
.venv/bin/python -m faultdebug.cli doctor --json
.venv/bin/python test/doctor_benchmark.py \
  --build-dir build-v12-baseline --require-runtime-smoke
.venv/bin/python test/build_systems/test_wrapper_contract.py
.venv/bin/python test/build_systems/test_instrumentation_profiles.py

.venv/bin/python test/v10_validation.py \
  --python .venv/bin/python \
  --build-dir build-v12-baseline \
  --ctest-dir build-v12-baseline \
  --grpc-build-dir build-v12-baseline \
  --install-prefix build-v12-baseline/install \
  --output build-v12-baseline/planning-evidence/acceptance-rerun
```

기존 v10 gate는 현재 v1.1 계약을 검증하며 CTest도 내부에서 실행한다.
`NOT RUN`에도 종료 코드 0이 나올 수 있으므로 `report.json`의 모든 row를 확인한다.
재실행할 때는 다른 output 이름을 사용해 이번 성공·실패 증거를 덮어쓰지 않는다.

첫 누락 재현의 로컬 스크립트는 다음으로 실행할 수 있다. permanent 회귀 테스트와
이식 가능한 fixture는 P1-01에서 추가한다.

```bash
.venv/bin/python build-v12-baseline/planning-evidence/faultdebug-v12-stride-proof.py
```
