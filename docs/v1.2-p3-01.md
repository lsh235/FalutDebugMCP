Both runs configured and built with provenance enabled, validated the source and
target provenance manifests, ran the named tests, and passed the existing
installed C/C++ consumer and store compatibility checks. Each built one wheel
and sdist, installed the wheel outside the checkout, and verified that imports
resolve to the installed package. The installed CLI passed capabilities,
doctor, a normal success run with no artifact, an opt-in success trace, and
MCP stdio initialization, required-tool discovery, `open_fault` success, and
the expected allowlist path error.

The final recheck uses the same 196-file source snapshot for both profiles, and
every recorded snapshot file matches its manifest hash. Generated `*.egg-info`

create profile-to-profile source drift. The raw reports are preserved separately
from the earlier local runs.

been observed.

## Current-source 1800-second soak

The final soak report (`output/v12-soak-final-ordered/report.json`) and target
artifact (`fault-3548752.fault`) are local generated evidence and are not part
of the source upload.
The suite is `PASS` 24/24 with no `NOT RUN`; the target ran for 1800.069 seconds,
reported `SIGSEGV` (11), and the runner observed 1800.162 seconds. The
independent fidelity oracle passed all 10 artifacts, including event order,
generation, nesting, module containment, and crash metadata.

Resource telemetry passed with 30 samples from 60 to 1800 seconds and no gap
over 60 seconds. Current RSS ranged from 2,208 to 2,284 KiB, peak RSS was
21,636 KiB, and the target held 5 file descriptors at every sample. The
observed recorder mapping was 12,768,064 bytes against the declared 33,554,432
byte budget.

The soak trace is explicitly **incomplete**: it reports 3,138,041 retained
thread events, 344,793 dropped events, 9,276 unstable snapshot records, and
`trace.complete=false`. Collector completion and the structural oracle apply
to surviving evidence; they do not imply that the trace is lossless. These
loss/partial fields remain in the report and artifact.
