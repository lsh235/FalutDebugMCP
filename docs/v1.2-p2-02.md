# v1.2 P2-02: per-run benchmark and normal-exit trace evidence

P2-02 connects each paired benchmark invocation to its target result, collector
result, trace quality, loss, and independently checked workload output. Successful
normal-exit trace collection is available only through the explicit
`faultdebug run --collect-success` option; ordinary successful runs continue to
produce no artifact.

## Changes

- Benchmark schema 2 adds a `run_id` and unique `sample_id` to each warmup and
  measurement, with a separate isolated artifact directory per invocation.
- The run summary reports target return code/signal, collector completeness and
  status flags, thread/RPC event and loss counters, and snapshot consistency.
- The benchmark reports launcher/process wall time separately from target wall
  time and target throughput. Missing values remain `NOT RUN`.
- The external C++ fixture has four fixed profiles: 1, 8, and 32 workers at 500
  iterations, and a 1-worker × 5000-iteration deliberate-overflow case. An
  independent Python uint64 implementation computes the exact expected output
  line. The gate checks it for every warmup and measurement and checks that all
  sample IDs and artifact directories are unique.
- Clean profiles require complete artifacts and zero reported loss. The
  overflow profile requires a clean baseline and an instrumented artifact with
  an overflow flag, nonzero loss, and `complete=false`.

## Verification

pairs for each profile. Every profile and each of its 18 invocations passed the
recorded contracts.

## Limits

These results validate the declared C++ call workload and the selected host only.
They do not establish a general overhead limit, application-wide performance,
cross-platform behavior, or release acceptance. The P2-03 independent libuv
comparison, full release gate, and current-revision 1800-second soak remain
separate work.
