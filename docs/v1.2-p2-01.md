# v1.2 P2-01: bounded collection and live snapshot consistency

P2-01 closes the collector readiness hang, serial-agent head-of-line blocking,
and mixed-record exposure during concurrent event/RPC writes. ABI v1 remains
unchanged. A live snapshot may contain individually stable rows while its
counters continue to move, so snapshots with observed instability are marked
incomplete and list omitted records as unresolved.

## Changes

- `collect_report` now treats the supplied timeout as one deadline shared by
  readiness and target-exit waiting. A missing readiness byte returns code 3
  with `phase=ready_timeout`; EOF or a non-`R` byte remains a startup failure.
- The serial Unix-socket agent applies a 250 ms receive deadline per accepted
  connection. An idle peer is closed without changing the agent's health state,
  so a later request and stop request can be handled.
- The decoder copies event, RPC, and crash records only after checking the
  publication marker and verifying the record sequence/timestamp before and
  after the copy. It rechecks thread/RPC counters and shared status around the
  read. Unstable records are omitted and listed under
  `snapshot_consistency.unstable_records`; `complete` is false for these rows,
  event/thread/module overflow, or incomplete/loss-marked RPC sidecars.
- Added a native two-writer fixture that repeatedly wraps the 8-slot event ring
  and RPC ring while reusing a thread slot. It is sampled from a live mmap.

## Verification

Reproductions before the fix showed:

- `collect_report` with an open readiness pipe and no byte exceeded an external
  0.5 s watchdog despite a 0.1 s target timeout (`timeout` exit 124).
- An accepted idle agent connection caused a following `status` request to
  time out and kept the server thread alive after `stop()` until the peer closed.
- An injected writer interleaving between publication check and record decode
  returned fields from two different event versions as one event.

## Limits

The stress fixture establishes bounded waits and per-record instability
reporting under the exercised Linux/Clang runtime. It does not claim a globally
atomic point-in-time view of a live process. The required 1800-second release
soak, cross-platform stress, and independent release audit remain `NOT RUN` and
are not acceptance claims for this work item.
