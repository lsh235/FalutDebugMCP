## 변경

- doctor compiler probe가 wrapper와 같은 선택 규칙을 사용한다. C는 설정된
  `FAULTDEBUG_REAL_CC` 또는 기본 `cc`, C++는 `FAULTDEBUG_REAL_CXX` 또는 기본
  `c++`를 단일 executable로 실행한다. doctor 전용 Clang fallback과 인자 분해는
  제거했다. 빈 설정은 wrapper와 같이 기본값을 뜻한다.
- 명시 compiler가 없거나 실행되지 않으면 `FAIL`이다. 설정하지 않은 기본 compiler가
  PATH에 없을 때는 `NOT RUN`이다. 따라서 잘못된 명시값을 건강한 PATH fallback으로
  숨길 수 없다. 출력에는 선택 경로, 실제 명령과 version이 담긴다.
- `FAULTDEBUG_RUNTIME_DIR`는 authoritative override다. 다른 build의 runtime으로
  대체하지 않는다. 후보 라이브러리는 별도 Python 프로세스에서 recorder startup을
  끈 채 load하고 필수 instrumentation hook 두 개를 확인한다. 빈 파일, 손상 파일,
  로드 불가 library, hook 누락은 `FAIL`; 후보 자체가 없으면 `NOT RUN`이다.
- `test/doctor_benchmark.py`는 C/C++ wrapper 실행 파일과 doctor 선택 결과가 같은지,
  `NOT RUN`/exit 2와 package 누락 `FAIL`/exit 1, invalid override 및 runtime fixture를
  검사한다. CTest에 실제 native `fd_c_chain`을 launcher로 띄우는 load/readiness/trace
  smoke를 등록했다. 진단의 library load 검사와 target 실행 검증은 별도 단계다.

재실행 command:

```bash
cmake -S . -B build-v12-baseline -G Ninja \
  -DCMAKE_C_COMPILER="$PWD/.tools/bin/clang" \
  -DCMAKE_CXX_COMPILER="$PWD/.tools/bin/clang++" \
  -DPython3_EXECUTABLE="$PWD/.venv/bin/python" \
  -DFAULTDEBUG_PYTHON_EXECUTABLE="$PWD/.venv/bin/python" \
  -DFAULTDEBUG_BUILD_TESTS=ON -DFAULTDEBUG_ENABLE_PROVENANCE=ON
cmake --build build-v12-baseline --parallel 2
ctest --test-dir build-v12-baseline --output-on-failure
```

`build-v12-baseline/p1-02/`에 보관했다.
