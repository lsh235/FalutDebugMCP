# v1.0 capability and support contract

v1.0 exposes a bounded capability contract so CLI and MCP clients can detect
the supported evidence interfaces before querying. Use:

```bash
fault-debug capabilities
```

MCP provides the same JSON through `get_capabilities`. The mandatory five
inspection tools are `open_fault`, `get_thread_trace`, `resolve_addresses`,
`get_function_source`, and `get_call_relations`. The contract also lists the
semantic RPC, session, store, and v0.9 incident tools, artifact/store versions,
limits, evidence classes, supported fatal signals, platform/toolchain, and
local-only security boundary.

Store health is read-only:

```bash
fault-debug evidence-health --db out/evidence.sqlite3
```

MCP provides `check_store`. Health checks use SQLite read-only mode, integrity
checking, base schema/table compatibility, additive v0.9 incident-table
availability, and migration state. They do not create, migrate, or modify a
database. A v0.8 schema-v2 store without incident tables reports
`compatible_additive_upgrade` and identifies the writable upgrade action.

The v0.9 incident tables are additive to base store schema v2. Existing v0.8
artifact/session/provenance queries remain compatible. Open the database once
through a writable `EvidenceStore` or an ingest/reindex command to initialize
the additive tables before using incident queries.

Support is bounded to the documented Ubuntu 24.04 x86_64, C11, Clang 18,
Python 3.12, CMake/Ninja path. Artifacts and source bundles are local and
verified before lookup. MCP uses local stdio; remote transport and encryption
are not provided. Evidence classes are never collapsed, shared session IDs do
not imply causal relations, and capability/health responses do not upgrade
unresolved provenance to trusted evidence.
