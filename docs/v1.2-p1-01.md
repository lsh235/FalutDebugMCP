# v1.2 P1-01: fixed physical thread-ring decoding

**Status: DONE.** Implemented on the v1.1.0 source revision
`6659a3baa7d84c9025f6d66dfdd421c53334c033`. The current worktree contains the
uncommitted implementation. It changes Python decoding and tests only; native ABI
layout and producer behavior are unchanged.

## Change

The native ABI reserves a fixed-size `fd_thread_ring` for every physical thread
slot. The header's `event_capacity` limits each ring's logical contents; it does
not move the next physical slot. The decoder had used that logical capacity to
calculate the next slot offset, so a configuration of 8 events shifted the
second slot by 424 bytes rather than the physical 196,648 bytes. The second
thread's published records were silently skipped.

`faultdebug/format.py` now names the ABI thread-ring stride and the fixed
thread/module/crash region offsets. It steps between thread headers using the
physical stride, limits event reads using the logical capacity, and bounds each
physical region by the next ABI region. `test/abi_decoder_contract.py` checks the
native-derived stride and rejects a mapping that ends inside the thread region.
`test/decoder_capacity.py` starts the real instrumented multithread fixture,
reads each thread's physical records independently from shared memory, then
compares the exact `(sequence, generation, type)` records returned by the Python
decoder. CTest runs it at capacities 1, 8, and 4096.

The later 1800-second release soak exposed one more ring-wrap contract: the
decoder returned committed events in physical slot order, so a wrapped ring's
sequence list was split at its write cursor. `faultdebug/format.py` now sorts
each decoded thread's committed records by sequence. The ABI contract builds a
synthetic physical order `[5, 6, 3, 4]` and requires decoded chronological order
`[3, 4, 5, 6]`. This changes report ordering only; event loss and unstable
snapshot markers remain explicit.

## Reproduce

From the repository root, with the existing project Python environment and a
configured Clang 18 CMake build:

```bash
cmake --build build-v12-baseline --parallel 2
ctest --test-dir build-v12-baseline --output-on-failure \
  -R 'fd_abi_probe|fd_python_abi_decoder|fd_python_decoder_capacity'
.venv/bin/python test/decoder_capacity.py build-v12-baseline/test/fd_threads

PATH="$PWD/.tools/bin:$PWD/.venv/bin:$PATH" \
FD_LAUNCHER="$PWD/.venv/bin/python -m faultdebug.cli" \
.venv/bin/python test/run_tests.py \
  --suite acceptance \
  --build build-v12-baseline \
  --output build-v12-baseline/planning-evidence/acceptance-rerun
```

The full v1.1 integrated gate also requires local Unix sockets and loopback gRPC;
its successful command and report are preserved in the evidence directory.
This task does not complete the other P1/P2 items or v1.2 release acceptance.
